# 真实面试复盘与下一轮准备

复用已有面试记录、简历和对应岗位 JD，接受零散回忆或回答思路，不要求逐字稿。已有模拟面试或 AI 演示不得混入真实记录。

## 输入与推进

1. 确认目标岗位、实际问题和回答回忆；轮次、面试结果、面试官反馈、下一轮时间/形式有就使用。没有结果时先完成共同复盘，不猜通过概率。没有 JD 时按岗位类别推断，标明依据。
2. 阅读 [prompt.md](prompt.md) 执行共同分析。只补问会改变判断的关键缺项；保留未记清和不知道的部分，不把回忆遗漏当成现场没答。未提供完整回答时不评价语速、语气或肢体表现。
3. 根据用户提供的实际结果选择一个分支：已通过读取 [references/passed.md](references/passed.md)；未通过读取 [references/not-passed.md](references/not-passed.md)；等待结果或尚未告知读取 [references/pending.md](references/pending.md)。结果或轮次冲突时先澄清，不选择有利的一种。通过不等于每道题都答好，未通过不等于每道题都答错。
4. 每题保留问题、原始回答回忆和实际追问，再引用具体记录分析亮点、待补与调整建议。优化后的回答另列；事实缺项写成待补，不回写原始记录。只有用户转述的反馈可作为反馈来源，不能把 AI 推断说成面试官的真实评价或确定淘汰原因。
5. 汇总优先行动与待补材料即可结束本轮复盘；不自动开始模拟面试。用户补充回忆或更新结果后，保留题号和原答，更新受影响部分与结果分支，不重复索要已有材料。下一轮计划不能写成已完成经历。

## 报告与交付

按 prompt.md 的结构保存完整 Markdown，再生成独立 HTML。正文按模块和题号展开，沿用蓝白版式；绿色表示有依据的亮点，橙色表示待补，蓝色表示调整建议。批注中的引用必须来自用户实际记录；不为配色改写原答。

先在报告中脱敏姓名、联系方式、学校、公司及项目专名和来源路径；保留岗位、业务类别、个人动作与真实数据，用一致代称代替专名。可用 `--redact` 补充需替换的文字；自动脱敏不能识别全部实体，交付前人工检查。私人输入和报告留在用户工作目录，不写入 Skill 包。

在本 Skill 目录运行（Python 3.9+，仅标准库）：

```bash
python3 scripts/render_report.py --input /absolute/report.md --output /absolute/report.html
```

渲染器同时写出脱敏 Markdown；不能以输入路径作为任一输出路径。多次传入 `--redact '需要隐藏的文字'` 可补充脱敏项。检查原答与分析完整、无正文截短、导航/折叠/全文阅读/打印可用后交付 HTML 与 Markdown。HTML 是阅读报告；分析与追问在宿主对话中进行。
